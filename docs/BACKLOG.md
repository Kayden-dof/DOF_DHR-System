## 화면 캡처 통제 (2026-08-26 요청)

> 개발이 완료되고 나면 화면 스크린샷을 찍을 때 스크린샷 찍는 계정 정보가 로그에
> 남도록 하고, 스크린샷을 찍더라도 하얀 화면만 찍히도록 하는 것도 고려.

**먼저 확인해야 할 것.** 웹 화면에서 캡처를 막는 것은 되지 않는다. `Win+Shift+S`,
`PrintScreen`, 휴대폰 카메라는 브라우저가 관여할 수 없는 경로다. 브라우저에서
`PrintScreen` 키를 잡아 서버에 남기는 코드는 쓸 수 있지만, 다른 캡처 도구를 쓰면
그냥 지나가고 카메라 촬영은 애초에 못 잡는다. **막았다고 믿게 만드는 쪽이 못
막는 것보다 위험하다.**

실제로 되는 것은 셋이다.

**1. 계정 워터마크 (지금도 가능 · 효과 큼)**
화면 전체에 로그인 계정명과 시각을 아주 옅게 깔아 둔다. 캡처를 막지는 못하지만
캡처된 그림에 누가 언제 봤는지가 함께 찍힌다. 유출이 생겼을 때 출처를 좁힐 수
있고, 무엇보다 찍는 사람이 그 사실을 안다. 억제 효과가 가장 큰 방법이다.
인쇄에는 나오지 않게 `@media print`에서 감춘다.

**2. 앱으로 감싸기 (진짜로 캡처가 막힘)**
Electron 등으로 감싸고 `win.setContentProtection(true)`를 켜면 Windows의
`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`가 걸려 캡처 결과가 검은 화면이
된다. 이건 OS가 보장한다. 다만 배포·갱신 경로가 하나 늘고, 현장 패드가
Android/iPad면 해당되지 않는다. **캡처를 정말 막아야 한다면 이 길뿐이다.**

**3. 조회 이력 (지금도 가능)**
캡처가 아니라 "누가 무엇을 열어 봤는가"를 남긴다. 인쇄는 이미 `record_print`에
남고 감사추적에도 들어간다. 화면 조회까지 남기려면 표가 하나 늘고 쓰기량이
크게 는다. 무엇을 지키려는지 정한 뒤에 범위를 잡는 편이 낫다.

**진행.** 1번은 넣었다 (`components/watermark.tsx`, 2026-08-27). 관리 화면과 현장
화면 모두에 계정명·사번·본 시각이 옅게 깔린다. 인쇄물에는 나오지 않는다.

2번은 현장 장비가 Windows PC로 확정되면 검토한다. **"캡처 로그"는 신뢰할 수
없으므로 넣지 않는다.**

## 실운영 착수 시 할 일 (2026-08-27 시연 준비에서 생김)

2026-08-27 대표 시연을 위해 **운영 DB에 시연 자료를 넣었다** (사용자 승인).
계정 000000 · 1001 은 개발 계정 표시가 켜져 있고 비밀번호가 단순하다.

실운영을 시작하는 날:

1. `node scripts/reset-db.mjs --prod --erase` 로 시연 자료를 비운다
2. 실제 계정과 기준정보를 화면에서 등록한다 (M1 전에 실제 로트 등록 금지)
3. **`scripts/reset-db.mjs` 를 저장소에서 지운다.** 실기록이 생긴 뒤에 존재하면
   안 되는 도구다. 시연 자료 일괄 정리라는 한 가지 목적으로만 임시로 있다
4. 000000 을 비활성화하거나 개발 표시를 해제하고, 남는 관리자 비밀번호를 바꾼다

선택 삭제 기능은 만들지 않았다. 삭제가 없는 시스템에서 시연 배치만 골라 지우는
기능은 그 자체가 기록 삭제 경로가 된다. 전체 초기화 하나만 둔다.

## 설비번호 입력

`process_record.equipment_id`가 스키마에 있고 제조기록서 비고란에 인쇄되는데,
현장 화면에 입력 칸이 없다. 설비를 기록으로 남길지 먼저 정해야 한다.
남긴다면 공정 시작 화면에 타일로 고르게 하는 것이 맞다 (키보드를 쓰지 않는다).
