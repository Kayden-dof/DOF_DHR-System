# 설치

새 제조소가 이 프로그램을 처음 세울 때 밟는 순서.

이 문서에는 **접속 정보나 비밀번호를 적지 않는다.** 값은 전부 환경 변수로
들어가고, 그 의미는 `.env.example` 에 적혀 있다.

---

## 0. 무엇이 필요한가

| | |
|---|---|
| PostgreSQL | 17 이상. Supabase 같은 관리형도 된다 |
| Node.js | 24 이상 |
| 서버 | Vercel 또는 Node 를 돌릴 수 있는 곳 |

**프린터는 A4 한 가지면 된다** (§7). 라벨 전용 프린터를 쓰려면 A4 라벨(스티커)
용지에 뽑아 떼어 붙인다.

---

## 1. 환경 변수

`.env.example` 을 보고 배포 환경에 넣는다. 반드시 채워야 하는 것은 셋이다.

| 값 | 왜 |
|---|---|
| `DATABASE_URL` | DB 접속 |
| `SESSION_SECRET` | 로그인 세션 서명. 32자 이상 |
| `CRON_SECRET` | 예약 작업(`/api/daily`)의 유일한 열쇠 |

`PRINT_SECRET` 은 **종이가 한 장이라도 나가기 전에** 넣는다. 인쇄물의 자료
식별자를 만드는 열쇠이고, 한 번 정하면 갈지 않는다 (§10). 비워 두면
`SESSION_SECRET` 에서 파생해 쓰는데, 그 상태로 세션 열쇠를 갈면 같은 자료가
다른 식별자를 내어 "자료가 바뀌었다" 로 읽힌다.

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

망 경계(`ALLOW_FROM` · `ALLOW_COUNTRY` · `ALLOW_REGION` · `ALLOW_CITY`)는
선택이다. 비어 있으면 어디서나 열린다 (§2.3).

---

## 2. DB 를 세운다

```bash
npm ci
npm run deploy:db -- --prod
```

`--prod` 를 빠뜨리면 아무 일도 일어나지 않는다. 대상 DB 를 눈으로 확인하라는
뜻이므로, 먼저 한 번 그냥 돌려 계획만 보는 편이 좋다.

이관은 여러 번 돌려도 안전하다. 계정이 하나도 없으면 **첫 계정을 만들고 그
비밀번호를 화면에 한 번만 찍는다.** 저장되지 않으므로 그 자리에서 받아 적는다.

> 첫 계정은 개발 계정으로 만들어진다. 비밀번호 초기화를 개발 계정만 할 수
> 있기 때문이다. **개발 계정 표시는 끌 수 없고**(§2.1) 품질책임자 역할도 받을
> 수 없다(§2). 실무에 들어가기 전에 운영용 시스템관리자를 따로 세우고,
> 기준정보는 그 계정으로 등록한다.

---

## 3. 코드를 올린다

Vercel 이면 저장소를 연결하고 위 환경 변수를 넣는다.

**DB 를 먼저, 코드를 나중에.** 순서가 바뀌면 배포된 코드가 아직 없는 함수를
부른다.

---

## 4. 설치를 확인하고 종이로 남긴다

```bash
node --env-file=<환경파일> scripts/iq.mjs
```

`reports/IQ-<일시>.txt` 가 나온다. 엔진 판·확장·이관 지문·만들어진 표와
트리거·S01~S05 의 실물·권한 상태를 조회로 확인한 기록이고, **"이 날 이 서버는
이런 상태였다" 의 근거**다. 이관을 올릴 때마다 다시 돌린다.

이 단계에서 아래는 아직 다르게 나온다. 정상이다.

| | 왜 |
|---|---|
| `IQ-16` 채번 규칙 0 | 5단계에서 넣는다 |
| `IQ-17` 제품표준서 0 | 5단계에서 넣는다 |
| `IQ-19` 운영용 시스템관리자 0 | 첫 계정은 개발 계정이다. 5단계에서 만든다 |

---

## 5. 화면에서 설정을 넣는다

로그인하면 **설정 > 개요**에 첫 설정 차례표가 있다. 앞의 것이 없으면 뒤 화면에
고를 것이 없는 순서로 놓여 있고, 비어 있는 자리마다 **무엇이 막히는지**를
적는다. 그 차례를 따라간다.

1. **회사 표시** - 이름·소재지·로고·색. 화면 머리줄과 모든 인쇄물에 나간다
2. **채번 규칙** - 없으면 번호를 만들 수 없다
3. **형명 체계** - 없으면 완제품 형명을 만들 수 없고 규격이 종이에 안 나간다
4. **품목** - 완제품 형명은 손으로 넣지 않는다. 체계에서 생성한다 (§10)
5. **공급자** - 입고에서 고를 곳
6. **설비** - 제품표준서의 공정에 건다
7. **제품표준서** - 공정·자재 구성표·장입 범위·시료 기준.
   서면과 대조한 뒤 **대조 확인**을 눌러야 작업 지시를 발행할 수 있다
8. **사용자** - 현장 화면을 쓸 작업자 계정

여기까지가 설치다. 이 뒤로는 개발 없이 화면에서 운영한다 (§2.0).

---

## 6. 백업을 세운다

**설정 > 백업**에서 내려받고 되돌린다. 자동 백업은 예약 작업이 돌린다
(`CRON_SECRET` 이 있어야 문이 열린다).

백업 파일은 사람이 정한 암호로 잠기고 서버 열쇠로 서명된다. **암호를 잃으면
되돌릴 수 없다.** 암호 보관 담당자와 예비 담당자를 정해 둔다.

받아 둔 백업이 실제로 되살아나는지는 정기적으로 확인한다.

```bash
npm run restore:check
```

---

## 7. 쓰기 전에 확인한다

| 확인 | 명령 | 무엇을 |
|---|---|---|
| IQ | `scripts/iq.mjs` | 서버에 무엇이 깔렸는가 |
| OQ | `DATABASE_URL=… node test/run.mjs` | 규칙이 실제로 막는가 |
| 인쇄 | `npm run test:print` | 종이가 자료와 같은가 |
| PQ | 서면 프로토콜 | 사람·종이·시스템이 맞물리는가 |

**정본 OQ 는 운영과 같은 PostgreSQL 에 대고 돌린 것이어야 한다.** 보고서 이름이
`OQ-PG-…` 면 실제 서버, `OQ-PGLITE-…` 면 개발 중 회귀 시험이다. 뒤의 것을
적격성 근거로 제출하지 않는다 (§8.0).

---

## 막혔을 때

- **번호가 안 만들어진다** - 채번 규칙이 없다 (설정 > 채번 규칙)
- **작업 지시를 발행할 수 없다** - 제품표준서가 서면 대조 확인·발효 전이다
- **규격이 종이에 안 나온다** - 형명 체계가 없다
- **화면이 막힌다 (접속지)** - 막힌 화면이 그때 값(주소·나라·시·도·시)을
  그대로 보여 준다. 그 값을 `ALLOW_*` 에 더하고 다시 배포한다. 앱 안에 푸는
  단추는 없다 (§2.3)
- **비밀번호를 전원 잃었다** - 개발 계정으로 초기화한다. 개발 계정까지 잃으면
  서버에서 `scripts/set-pin.mjs` 를 쓴다. 그 실행은 감사추적에 남는다

규칙이 정상 작업을 막는 것처럼 보이면 **완화하지 말고 먼저 물어볼 것** (§12).
차단은 다섯 개뿐이고 전부 사후 복구가 불가능한 항목이다.
